## 2. What Went Well

- **Full Feature Completion:** All 4 stories delivered in dependency order — shared schema → API → form → integration — with no missing pieces.
- **Robust Review Loop:** Two high-severity bugs in the EmailOctopus duplicate-contact-update logic were caught and fixed through review iterations. Iteration 1 discovered message-loss bug; iteration 2 discovered the "fix" would 404 every update. Without review, both would have shipped.
- **Correctness Under Pressure:** The implementation correctly handles the complex EmailOctopus upsert flow (create-contact → if-duplicate-exists, update with MD5-hashed contact id → store message), including edge cases (trimmed honeypot check, 6s timeouts, single-read error parsing).
- **Accessible UX:** Form validation (blur + submit), `aria-live` error announcements, honeypot hidden via CSS (`sr-only` positioning, `aria-hidden`, `tabIndex={-1}`), and no-JS `mailto:` fallback all verified working.
- **Error Handling:** Comprehensive failure branching — schema validation, honeypot check, EmailOctopus network/timeout/misconfiguration, retry with preserved field values — all implemented.

Two high-severity bugs were found in the same code region, and there is zero automated test coverage. This compounds the risk for future changes.
- **Deferred Observability & Hardening:** Four items logged for later:
  - Rate limiting / CSRF / origin protection on `/api/contact` (honeypot is the only anti-abuse layer; vulnerable to direct script POSTs)
  - Automated test coverage for schema/route/form branching
  - Honeypot-trip observability (count/log to verify anti-spam is working)
  - EmailOctopus custom-field length limits unverified against schema bounds (5000-char message, 200-char name)

## 7. Key Learnings

1. **Infrastructure ≠ Process:** Building the debug overlay tool (Epic 2) didn't automatically trigger design-iteration discipline. The *process* of using the tool for rapid feedback loops still needs to be established and enforced.

2. **High-Risk Code Needs Tests Early:** The contact schema/route/form code had 2 high-severity bugs in the same code path, both caught by human review, zero caught by tests (because none exist). This is the repo's highest-branching code and should have been paired with automated test coverage from the start.

3. **Review Loops Work — But Tests Work Better:** While the review loop successfully found and fixed real bugs, automated tests catch regressions faster and give ongoing confidence. For code this complex, both are needed.

4. **Design Iteration Scope Matters:** Deferring design refinement is pragmatic, but the gap should be explicitly tracked and scheduled — not left as implicit "we'll do it later" debt.
