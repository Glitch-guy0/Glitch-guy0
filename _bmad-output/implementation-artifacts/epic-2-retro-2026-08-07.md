## 2. Team Reflection & Discussion Highlights

### What Went Well
- **Modular Component Breakdown:** Breakdown of sections (`HeroSection`, `ServicesSection`, `ProjectsSection`, `AboutSection`, `SkillsSection`, `ExperienceSection`) and UI primitives (`ButtonPrimary`, `ButtonSecondary`, `ProjectCard`, `SkillPill`, `FormField`, etc.) created a highly maintainable foundation.
- **Single-Sourced Copy Module:** Integrated `src/content/` typed copy module early in Story 2.1, preventing placeholder text across all 6 sections.
- **Responsive Layout Execution:** Sections adapt cleanly across mobile (360px), tablet (768px), and desktop (1280px) viewports without horizontal layout breaks.

### Key Feedback & Iteration Requirement Surfaced by Project Lead
- **Design Iteration Need:** Prajwal highlighted: *"The design is not like what I wanted — need iteration. To improve the iteration process, each component should have an `::after` pseudo element with component name so that during iteration it's easier to point and ask for changes."*
- **Debug Component Labeling:** Implemented environment-gated `NEXT_PUBLIC_DEBUG_COMPONENTS` toggle in `.env.example` and `DebugOverlay.tsx` island to render floating green `:: <ComponentName>` labels via `::after` pseudo-elements on `[data-component]` elements during debug mode only. Zero DOM/CSS output in client production builds.
- **Testing Utility Isolation:** Reorganized testing scripts (`axe-scan.cjs`) into `scripts/testing/` to isolate test tooling and keep project root/scripts clean for future iterations.
