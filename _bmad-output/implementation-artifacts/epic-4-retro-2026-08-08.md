## 2. What Went Well

- **Clean single-pass delivery:** No `intent_gap` or `bad_spec` loopbacks — the spec held up through implementation.
- **High-severity catch before ship:** The review caught a text-clipping bug — 3 work-statement lines and the skills-pills line overflowed the usable page width by up to 68% with no word-wrapping. Fixed and re-verified by re-measuring rendered text width against page bounds.
- **Rigorous verification:** Verification went beyond "PDF opens fine" — it measured text-width overflow programmatically and decoded the PDF byte stream to confirm content is genuinely single-sourced from `src/content/`, not duplicated.
- **Single-sourcing held:** No orphan copy — resume title, headline, and contact line all trace back to `src/content/index.ts` and `CONTACT_EMAIL`, including a mid-review fix that replaced two hardcoded literals that had crept in.

---

## 3. Challenges & Follow-Up Needed

- **Resume content is too dense (new finding, this retro):** Prajwal flagged that the resume PDF carries more text than makes sense for a one-page resume. This is a content/authoring issue in `src/content/` (work statements, skills), not a defect in the generation pipeline — the PDF is faithfully rendering what the content module gives it. Needs a content rethink, not a code fix.
- **Three deferred, non-blocking gaps** (tracked in `deferred-work.md`, left as-is per team agreement):
  - `predev` regenerates the PDF once at dev-server startup only — editing `src/content/index.ts` during an already-running `next dev` session leaves the PDF stale until restart.
  - The footer's cache-busting query (`?v=1`) is a static literal, not a content hash/timestamp — a redeployed PDF with unchanged query string can serve a stale cached copy.
  - The only automated PDF validity check is a byte-size floor; nothing asserts extracted PDF text matches current content.
- **Carried-forward flag from Epic 3 (not an Epic 4 issue, but relevant now):** Epic 3's retrospective flagged "Test Coverage for Contact Schema & Route" as highest-priority, due **before Epic 5**. It remains `open` in `action_items`. Epic 4 didn't touch that code path, so nothing to report against Epic 4 itself — but Epic 5 is next, so this is worth surfacing loudly rather than losing track of it.

## 7. Key Learnings

1. **Verification depth pays off:** Measuring actual rendered text width against page bounds — not just "does it open" — is what caught the clipping bug. Worth keeping as the verification bar for future content-rendering work.
2. **Single-sourcing works as designed:** Content changes (like the density rethink) are pure content-module edits with zero code changes needed — confirms the architecture decision (AD-4) is paying off.
3. **Deferred items need an active decision point, not silent carry-forward:** The Epic 3 test-coverage item explicitly said "before Epic 5" two epics ago and is still open. A retro flag isn't enough by itself — it needs a scheduled decision before the dependent epic starts.
